$ sprout

your-project/ ├── only what matters ├── what changed, and where └── a map your AI agent can read

Sprout is a directory tree that understands projects. It respects your .gitignore, marks changes, sizes and hotspots in place, shows a pull request as a tree, tells you where to start reading, and gives LLMs a compact map with real signatures. It works on local folders and GitHub URLs, as one small binary.

Includes shell completions and man sprout.

The script checks the SHA-256 and never uses sudo (read it first). Or use Homebrew, or the .deb, .rpm, .apk and Arch packages on the releases page.

Or download the zip for amd64 or arm64 from the releases page.

Needs Go 1.22 or newer. Add completions with sprout --completion zsh (or bash, fish, powershell).

One project, five ways

This is real Sprout output for trailhead, a sample trail-map app with a Go API and a React frontend, partway through a feature branch. Pick a command to see what it shows.

    $ sprout -L 2

    Context that fits the window

    sprout --ai writes a plain-text map for a prompt or an agent: what the project is, its stack, entry points, CI and config, uncommitted work, recent hotspots, and the layout. It never includes file contents.

    Below the layout come the key files: the code the rest of the project uses most, with its function and type signatures, so a model knows your APIs without reading every file.

    You set a token budget. Folders open breadth-first while the map still fits, and key files get what's left. Drag the slider to watch the budget get spent.

    smallereverything
    $ sprout --ai --budget 300

    Know where to start reading

    sprout --entry gives a new teammate, or you six months from now, a reading order: what the project is, where execution starts, then the files the rest of the code depends on most.

    Sprout ranks by real imports and references, parsed from Go, TypeScript, JavaScript, Python, Rust, Java and Kotlin. Tests don't count.

    sprout github.com/owner/repo --entry

    It works on repositories you haven't cloned, too. Sprout makes a temporary clone and removes it afterwards.

    $ sprout --entry

      Give your coding agent the map

      Sprout runs as an MCP server. Claude Code, Cursor and other agents can get oriented in one call, instead of spending their context on ls -R, find and opening files one by one.

      The server is read-only, and paths can't leave the project, even through symlinks. MCP setup

      claude mcp add sprout -- sprout mcp
      • sprout mcp/
      • ├── project_mapthe --ai map with key signatures
      • ├── reading_orderwhere to start, and why
      • ├── treeany folder, with git status or churn
      • └── diff_treewhat a branch changed

      Fits the way you already work

      Plain sprout is usually enough. When it isn't, the flags follow conventions you already know, and your defaults live in a config file.

      • sprout/
      • ├── .gitignoredecides what's shown, and hidden entries are always counted
      • ├── --only --ignoregitignore patterns like 'src/**/*.ts', plus .sproutignore
      • ├── --size --sorttrue folder totals, largest or newest first
      • ├── --changed-withinonly what you touched this week: 7d
      • ├── --max-filestame folders with 400 icons
      • ├── --hyperlinkclick a name to open the file
      • ├── .sproutrcper-project defaults, plus ~/.config/sprout/config
      • ├── --jsona versioned schema for scripts and PR bots
      • └── --completionbash, zsh, fish and PowerShell, plus man sprout

      Fast on big repositories

      Sprout only reads what the output needs and parses source files in parallel. These are timings on Kubernetes (31,412 files) on a laptop with a warm cache.

      Reproduce them with bench_test.go in the repository.

      CommandTime
      sprout0.47 s
      sprout -L 20.25 s
      sprout --size -L 10.57 s
      sprout --entry1.0 s
      sprout --ai1.1 s
      find . -type f0.49 s
