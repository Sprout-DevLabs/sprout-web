Sprout documentation

Sprout is a single binary. Everything below is also in sprout --help.

Install

# macOS and Linux
brew install sprout-devlabs/tap/sprout

# Anywhere with Go 1.22+
go install github.com/Sprout-DevLabs/sprout@latest

Prebuilt archives for Linux, macOS and Windows (amd64 and arm64) are on the releases page, with checksums. Git features need git on your PATH. Nothing else does.

Basics

sprout              # current directory
sprout src          # another directory
sprout src -L 2     # flags go before or after the path
sprout -a           # everything, including hidden and ignored entries

The tree ends with a summary line, the same as tree. It also counts anything Sprout hid:

3 directories, 46 files (6 hidden or ignored, --all to show)

What gets hidden

Inside a git repository, .gitignore decides. Sprout asks git for the list of tracked files plus untracked files that aren't ignored. Nested .gitignore files, negations (!keep.log) and your global excludes all behave exactly as they do in git.

Outside git, Sprout hides common build and dependency directories: node_modules, dist, build, target, obj, coverage, .venv, venv, __pycache__, .cache, .next, .nuxt, .pytest_cache, .mypy_cache, .idea, .vscode, .DS_Store, *.egg-info.

Dotfiles are hidden in both cases, and .git is never shown.

FlagEffect
--hiddenShow dotfiles.
--no-ignoreDon't apply .gitignore or the built-in list. Dotfiles stay hidden.
-a, --allBoth of the above.
--ignore LISTAlso hide these names or globs, comma-separated: --ignore '*.log,fixtures'. Matches file and directory names, not paths.

--ai: project map for LLMs

sprout --ai | pbcopy           # macOS
sprout --ai | xclip -sel c     # Linux
sprout --ai --budget 800       # smaller map

This prints a plain-text overview meant to be pasted into a prompt or loaded by an agent. From top to bottom:

  • The README's first prose line. Headings, badges and HTML are skipped.
  • stack: detected from manifests like go.mod, package.json, pyproject.toml and Cargo.toml. Every one found is listed.
  • languages: share of files, counting programming and markup languages only.
  • git: the branch and any uncommitted changes, plus the five files with the most commits in the last 90 days.
  • entry points: files like main.go, index.ts, app.py and main.rs, outside tests and examples.
  • config: Dockerfiles, compose files, CI workflows, tsconfig.json, *.config.* and similar.
  • structure: one line per directory, with its files listed inline.

How the budget works

--budget is an approximate token count (default 2000, at about 4 bytes per token). If the full structure fits, you get all of it. Otherwise every top-level directory starts as a one-line summary like internal/ (84 files, mostly .go). Directories then open breadth-first while the map still fits. examples/, test/, tests/, testdata/, fixtures/, vendor/ and third_party/ open last. A directory too big to open doesn't stop its smaller siblings from opening.

Only file and directory names go into the map, plus the README's first line. Sprout never reads or prints the contents of any other file.

--diff: a revision range as a tree

sprout --diff main...HEAD      # what this branch changed since it forked
sprout --diff HEAD~3           # last three commits plus working tree changes
sprout --diff v1.0..v1.1 -L 2  # between tags, collapsed to depth 2

This shows only the changed paths, with M A D R markers and +/- line counts. Directories show how many files changed below them, plus line totals. With -L, deeper subtrees collapse into those totals. Any revision syntax git accepts works, with one exception: a value starting with - is refused, so it can't be mistaken for a git option.

Directories show (N changed), so changes stay visible when -L collapses a folder. The header shows the current branch. This works from any subdirectory of a repository.

--churn: hotspots

sprout --churn
sprout --churn --since '90 days ago'
sprout --churn --git -L 2

Each path shows the number of commits that touched it, with a bar scaled against the busiest file. Directories are scaled against the busiest directory and count each commit once. Higher counts are colored yellow, then red. --since accepts any date git understands. Churn reads the history in a single git log pass. On very large histories, use --since to keep it quick.

--json

This prints the tree, detected projects and summary as a single JSON document. It combines with every other flag: --git adds status and changes, --churn adds churn, and --diff adds added and deleted.

{
  "schemaVersion": 1,
  "name": "demo",
  "root": "/home/you/demo",
  "gitAware": true,
  "projects": [{ "manifest": "go.mod", "language": "Go", "packageManager": "go modules" }],
  "summary": { "directories": 1, "files": 2, "bytes": 30, "skipped": 1,
               "languages": { "Go": 1, "Go modules": 1 } },
  "tree": {
    "name": "demo", "type": "directory",
    "children": [
      { "name": "go.mod", "path": "go.mod", "type": "file", "size": 12 },
      { "name": "src", "path": "src", "type": "directory", "changes": 1,
        "children": [
          { "name": "main.go", "path": "src/main.go", "type": "file", "size": 18, "status": "M" }
        ] }
    ]
  }
}
Node fieldNotes
pathRelative to the root and always slash-separated, including on Windows. Omitted on the root node.
type"file" or "directory"
sizeBytes, files only
truncatedA directory that wasn't expanded because of --depth
errorA directory that couldn't be read, e.g. "permission denied". The walk carries on past it.
status, changes--git / --diff
added, deleted--diff line counts, summed on directories
churn--churn commit count

Empty fields are omitted, and projects is always an array. schemaVersion changes only when an existing field changes meaning or is removed, never when a field is added.

MCP server for coding agents

sprout mcp [root] speaks the Model Context Protocol over stdio. The root defaults to the directory it's started in.

Claude Code

claude mcp add sprout -- sprout mcp

Cursor, Claude Desktop and other clients

{
  "mcpServers": {
    "sprout": { "command": "sprout", "args": ["mcp"] }
  }
}

Clients that don't start servers in the project directory can pass it explicitly: "args": ["mcp", "/path/to/project"].

Tools

ToolArgumentsReturns
project_mappath?, budget?The --ai map. Its description tells agents to call it first.
treepath?, depth? (default 3), all?, git?, churn?, since?A tree of a subdirectory
diff_treerev, path?, depth?The --diff view

Safety

  • path must stay inside the root once .. and symlinks are resolved. Absolute paths are refused.
  • rev can never become a git option.
  • Tool output refers to paths relative to the root, never your home directory.
  • The server is read-only. Nothing it does writes to disk.

Exit codes: 0 success, 1 runtime error (missing path, not a git repository), 2 bad flags or arguments.

FAQ

No colors?

Colors only appear when the output goes to a terminal. They're turned off when NO_COLOR is set or TERM=dumb.

I have a directory called mcp

sprout mcp starts the server. Use sprout ./mcp to see the directory's tree.

How is this different from tree?

For a plain listing it isn't very different, and that's deliberate: sprout -L 2 works the way you'd expect. The difference is the defaults (.gitignore, counting what's hidden) and the views tree doesn't have: --ai, --diff, --git, --churn and MCP.
