Sprout documentation

Sprout is a single binary. Everything here is also in sprout --help and man sprout.

Install

install.sh works out your OS and architecture, downloads the release archive, and checks its SHA-256 against the release's checksums.txt before installing. It installs to /usr/local/bin if that's writable and to ~/.local/bin otherwise, and it never uses sudo. You can pin a version with SPROUT_VERSION=v0.2.0 and choose the location with SPROUT_INSTALL_DIR.

Homebrew and the Linux packages install shell completions and the man page too. Every release also has plain archives for Linux, macOS and Windows on amd64 and arm64. git is only needed for git features.

Basics

sprout                     # current directory
sprout src -L 2            # flags go before or after the path
sprout -a                  # everything, including hidden and ignored entries
sprout github.com/o/repo   # a repository you haven't cloned

The tree ends with a summary line, like tree's. It also counts anything Sprout hid:

15 directories, 15 files (4 hidden or ignored, --all to show)

What gets hidden

Inside a git repository, .gitignore decides. Sprout asks git for tracked files plus untracked files that aren't ignored, so nested .gitignore files, negations and your global excludes behave exactly as they do in git.

Outside git, these are hidden: node_modules, dist, build, target, obj, coverage, .venv, venv, __pycache__, .cache, .next, .nuxt, .pytest_cache, .mypy_cache, .idea, .vscode, .DS_Store, *.egg-info.

Dotfiles are hidden in both cases, and .git is never shown. A .sproutignore in the target directory adds patterns on top.

FlagEffect
--hiddenShow dotfiles
--no-ignoreDon't apply .gitignore, .sproutignore or the built-in list
-a, --allBoth of the above

Filtering

--ignore, --only and .sproutignore all use gitignore syntax. Flags can be repeated or comma-separated.

PatternMatches
*.logAny .log file at any depth (no slash means match the name)
src/genExactly src/gen from the root (a slash anchors it)
build/Directories named build only
docs/**/*.pngPNGs anywhere under docs (** crosses folders)
!keep.logRe-include something an earlier pattern hid (the last match wins)
sprout --only '*.go' --ignore '*_test.go'      # Go sources, no tests
sprout --only 'web/src/**/*.tsx'                # one part of a frontend
sprout --changed-within 2d                      # files modified in the last two days
sprout --max-files 5                            # at most 5 files per folder, then "… 37 more files"

--only prunes folders it leaves empty. --changed-within accepts 30m, 12h, 7d, 2w or any Go duration. Everything these flags hide is counted in the summary line.

Sizes and sorting

sprout --size -L 1                  # folder totals, du-style
sprout --size --sort size -L 2      # largest first
sprout --sort time -r               # oldest first
sprout --dirs-first --si --size     # folders first, powers of 1000

Folder totals are true totals. When -L collapses a folder, Sprout still measures everything inside it without listing it. Sorting by size or time works the same way, so a collapsed folder sorts by what it contains. Sizes are shown du -h style (4.2K, 1.3M), in powers of 1024 unless you pass --si.

Config files

Default flags go in a config file, one per line:

# ~/.config/sprout/config
--hyperlink
--ignore=*.snap,fixtures/
--budget 4000
Read in this order
User$SPROUT_CONFIG, else $XDG_CONFIG_HOME/sprout/config, else ~/.config/sprout/config (%AppData%\sprout\config on Windows)
ProjectThe nearest .sproutrc in the target directory or above it
Command lineAlways wins. Turn a boolean off with --git=false

--ignore and --only patterns add up across all three. --no-config skips both files. A mistake in a config file names the file and line. A repository you map by URL never has its .sproutrc applied.

--ai: project map for LLMs

sprout --ai | pbcopy           # macOS
sprout --ai | xclip -sel c     # Linux
sprout --ai --budget 800       # a smaller map

This prints a plain-text overview for a prompt or an agent. From top to bottom:

  • The README's first prose line
  • stack and languages, from manifests and file counts
  • git: the branch, uncommitted changes, and the 5 most-changed files in the last 90 days
  • entry points and config (Dockerfiles, CI workflows, compose files, tsconfig.json and so on)
  • structure: one line per folder, with its files inline
  • key files: the files the rest of the code uses most, with their function and type signatures
## key files (most used first)
web/src/lib/types.ts (used by 5): export interface Trail; export interface Report; export type Units
internal/trails/store.go (used by 3): type Store struct; func NewStore(db *sql.DB) *Store; …

How the budget works

--budget is an approximate token count (default 2000, at about 4 bytes per token). The structure gets three fifths of it. Every top-level folder starts as a one-line summary like internal/ (84 files, mostly .go), and folders open breadth-first while the map fits. Tests, examples, fixtures and vendored code open last. Key files get the rest of the budget.

How key files are found

Sprout reads source files, extracts top-level declarations with their signatures, and resolves local imports. Files are ranked by how many other files import or reference them. Tests don't count, and are never read for this.

LanguageHow
GoGo's own parser. Module imports and same-package references both count, so single-package programs rank too.
TypeScript, JavaScriptexport declarations, and relative import/require/import() (./x.js finds x.ts)
PythonTop-level def/class (not _private), and relative, dotted and src/ imports
Rustpub items, mod x; and use crate::…
Java, KotlinPublic types and top-level declarations, and import under any source root
Only file and directory names, the README's first line and declaration signatures go into the map. Function bodies and other file contents never do. TypeScript path aliases (@/…) aren't resolved yet.

--entry: where to start reading

$ sprout --entry
Reading order for trailhead

  1. README.md                  what the project is
  2. cmd/api/main.go            entry point
  3. web/src/main.tsx           entry point
  4. web/src/lib/types.ts       used by 5 files
  5. web/src/lib/api.ts         used by 4 files

The order is the README, then entry points, then the most-used files from the same ranking as --ai, up to 15 steps.

--diff: a revision range as a tree

sprout --diff main...HEAD      # what this branch changed since it forked
sprout --diff HEAD~3           # the last three commits plus uncommitted changes
sprout --diff v1.0..v1.1 -L 2  # between tags, collapsed to depth 2

This shows only changed paths, with M A D R marks and +/- line counts. Folders show how many files changed below them, plus totals, and -L collapses deeper folders into those totals. Any revision git accepts works, but a value starting with - is refused so it can't act as a git option.

--git: working tree status

MarkMeaning
MModified
AAdded (staged)
DDeleted, shown where the file used to be
RRenamed
?Untracked
UMerge conflict

Folders show (N changed), so changes stay visible when -L collapses a folder. This works from any subdirectory of a repository.

--churn: hotspots

sprout --churn
sprout --churn --since '90 days ago'
sprout --churn --git -L 2

This shows the number of commits that touched each path, with a bar scaled against the busiest file (folders against the busiest folder). High counts turn yellow, then red. For very large histories, add --since.

--stats

File and folder counts, total size (KiB/MiB, or kB/MB with --si), every detected stack, and a count of files per language.

--json

This prints the tree, detected projects and summary as one JSON document, and combines with every other flag. schemaVersion only changes when an existing field changes meaning or is removed. Adding fields doesn't change it.

Node fieldNotes
name, path, typepath is relative to the root and always uses /. type is "file" or "directory"
size, modifiedBytes, and RFC 3339 UTC. Folders get their total with --size, and their newest file's time
truncated, moreFilesCollapsed by --depth; files left out by --max-files
errorAn unreadable folder, e.g. "permission denied". The walk carries on past it
status, changes--git / --diff
added, deleted--diff line counts, summed on folders
churn--churn commit count

Remote repositories

sprout github.com/charmbracelet/bubbletea --ai
sprout https://gitlab.com/group/project --entry
sprout git@github.com:acme/private.git --churn -L 2

Any git URL (https, ssh, git@host:path, file) or host/owner/repo shorthand is cloned into a temporary folder, mapped, and removed, even if you press Ctrl-C. A path that exists on disk is always treated as local. Sprout fetches one commit by default. With --git, --churn or --diff it fetches the full history but not old file contents. Private repos use your usual git credentials. The cloned repo's .sproutrc is ignored.

MCP server for coding agents

sprout mcp [root] speaks the Model Context Protocol over stdio. The root defaults to the directory it starts in.

Claude Code

claude mcp add sprout -- sprout mcp

Cursor, Claude Desktop and other clients

{
  "mcpServers": {
    "sprout": { "command": "sprout", "args": ["mcp"] }
  }
}

If your client doesn't start servers in the project directory, pass the path: "args": ["mcp", "/path/to/project"].

ToolArgumentsReturns
project_mappath?, budget?The --ai map, key files included. Agents are told to call it first
reading_orderpath?The --entry list
treepath?, depth? (default 3), all?, git?, churn?, since?A tree of a folder
diff_treerev, path?, depth?The --diff view

Safety

  • path must stay inside the root once .. and symlinks are resolved. Absolute paths and URLs are refused, so the server never clones anything.
  • rev can't become a git option.
  • Output shows paths relative to the root, never your home directory.
  • The server is read-only.

Completions and man page

sprout --completion bash > ~/.local/share/bash-completion/completions/sprout
sprout --completion zsh  > "${fpath[1]}/_sprout"
sprout --completion fish > ~/.config/fish/completions/sprout.fish
sprout --completion powershell >> $PROFILE
sprout --man | man -l -          # Linux; Homebrew installs `man sprout`

Completions cover every flag, the --sort values, git branches and tags for --diff, and folders for the path. They're generated from the same definitions the binary parses, so they can't go out of date.

Performance

These are measured on Kubernetes (31,412 files) on a laptop with a warm cache:

CommandTime
sprout0.47 s (find: 0.49 s)
sprout -L 20.25 s
sprout --size -L 10.57 s
sprout --entry1.0 s
sprout --ai1.1 s

Sprout only reads file metadata when the output uses it, parses source files in parallel, and never reads tests or vendored code for the code graph. The repository's bench_test.go reproduces these numbers.

FAQ

Why are there no colors?

Colors and links only appear when output goes to a terminal. NO_COLOR or TERM=dumb turns colors off.

I have a directory called mcp

sprout mcp starts the server. Use sprout ./mcp for the directory.

How is this different from tree?

For a plain listing it isn't very different, and sprout -L 2 behaves the way you'd expect. The difference is the defaults (.gitignore, counting what's hidden) and the views tree doesn't have: --ai, --entry, --diff, --git, --churn, remote repositories and MCP.

Does --ai send my code anywhere?

No. Sprout has no network access except when it clones a repository you asked for. --ai only prints text, and you decide where it goes.
